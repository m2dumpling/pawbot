# pawbot 0.4.2 release notes

This patch release fixes self-update on Windows for persistent `uv` and `pipx`
installations. It also makes the v0.3.9-to-current feature changes easier to
use by documenting the WebUI, CLI, and CI entry points separately.

## Windows self-update

When `pawbot update` is launched from a persistent Windows tool installation,
Windows locks the running `pawbot.exe`. Pawbot now hands the package-manager
command to a detached PowerShell helper, exits the current process, and lets
the helper update the package after the launcher is released.

The command remains:

```powershell
pawbot update
```

If a v0.4.1 Windows installation cannot run its old updater because of
`os error 32`, close Pawbot and run `uv tool upgrade pawbot-ai` once to install
this fixed version.

After the command returns, verify the result with:

```powershell
pawbot --version
```

Provider credentials, sessions, recordings, workspaces, and channel settings
are not reinitialized. A temporary update log path is printed if the handoff
is used.

## Usage guide

The README now includes a compact migration map from v0.3.9. In short:

- use the WebUI for live execution records, regression samples, offline replay,
  raw inspection, and Tool approval;
- use the CLI for the deterministic Agent Harness and trace commands;
- use the quality gate locally or in CI before submitting Agent changes.
