# pawbot 0.3.2 release notes

This patch release improves the first-install path across macOS, Linux, and
Windows. It focuses on making installation failures explicit and ensuring that
the CLI is verified before the installer reports success.

## Highlights

- Preflights Python `venv`/`ensurepip` before creating the managed environment.
- Gives Debian/Ubuntu users a version-specific `python3.x-venv` repair command
  when a minimal image is missing the required package.
- Stops immediately on installation failures instead of printing a misleading
  WebUI or `pawbot` startup command.
- Verifies `pawbot --version` after installation and reports the exact launcher
  path when the current shell does not resolve `pawbot` through `PATH`.
- Adds a Windows `.cmd` launcher with user `PATH` setup and handles launcher
  paths containing spaces.
- Adds installer smoke coverage for Ubuntu, macOS, and Windows plus a POSIX
  missing-venv regression test.

## Upgrade

```bash
uv tool install --force --upgrade pawbot-ai
pawbot --version
```

For a fresh install, use the platform installer shown in the main
[README](../../README.md). Existing configuration, sessions, workspaces, and
recordings remain under the user's local `~/.pawbot/` data directory.

## Boundaries

- System packages such as `python3.x-venv` are not installed silently. The
  installer reports the exact repair command and exits when they are missing.
- The installer smoke job verifies CLI installation in headless CI; opening a
  browser remains a desktop-only first-run behavior.
