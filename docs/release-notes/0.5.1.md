# pawbot 0.5.1 release notes

This patch release hardens the existing Agent runtime and provider boundary.
It does not add a new orchestration framework or distributed service layer.

## DeepSeek provider coverage

The DeepSeek path now has a dedicated contract test suite covering:

- V4 model capability metadata and the 1M-token context window;
- reasoning effort and provider-native thinking controls;
- historical Tool Call messages and missing `reasoning_content` fields;
- streaming Tool Call argument accumulation and reasoning deltas;
- usage accounting and structured provider error metadata.

DeepSeek is the provider path with the deepest validation in this repository.
Other providers continue to use the shared compatibility adapter, but their
endpoint-specific model lists, headers, streaming events, and error semantics
must be verified separately.

## Runtime guardrails

Self-hosted processes can opt into local request limits with:

```text
PAWBOT_MAX_CONCURRENT_REQUESTS
PAWBOT_MAX_CONCURRENT_PER_SENDER
PAWBOT_PROVIDER_MAX_INFLIGHT
PAWBOT_PROVIDER_RPM
```

Provider-specific overrides such as `PAWBOT_DEEPSEEK_RPM` take precedence.
These are process-local controls; multi-instance deployments still need an
external gateway or distributed quota service.

## Fault boundaries and validation

The quality gate now includes Provider contract tests and fault-injection
checks for recovery, incomplete/corrupted recording samples, Provider errors,
and Outcome invariants. The release was verified with the complete Python test
suite, WebUI tests and production build, Ruff, basedpyright, the Agent Harness,
Record & Replay fixtures, and `uv build`.
