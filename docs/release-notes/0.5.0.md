# pawbot 0.5.0 release notes

This feature release makes task completion and side-effect recovery explicit in
the Agent runtime. It extends the existing execution trace and Record & Replay
surfaces without changing the basic WebUI, CLI, SDK, or provider setup flow.

## Runtime task verification

`TaskContract` is now a public runtime capability. An SDK caller or a one-shot
CLI run can declare what “done” means using final text, successful tools,
tool-result content, workspace files, file content, or a caller-owned
synchronous validator.

The result is explicit:

- `passed`: every declared condition passed;
- `failed`: the Agent returned a result, but one or more conditions failed;
- `not_evaluable`: the run was cancelled or failed, or a required validator was
  unavailable.

When a declarative check fails, the failed conditions are returned to the Agent
as model-facing feedback. The Agent may correct the work and continue while the
normal iteration, tool, time, token, and cost budgets still allow it.

Example:

```python
from pawbot import TaskContract

result = await bot.run(
    "Create and verify the release note.",
    task_contract=TaskContract(
        id="release-note",
        final_content_contains=("verified",),
        required_tools=("write_file", "read_file"),
        required_files=("CHANGELOG.md",),
    ),
)
print(result.task_evaluation)
```

For a one-shot CLI check:

```bash
pawbot agent --message "Create and verify the release note" \
  --task-contract contract.json
```

## Safer side-effect recovery

Tools can declare their side-effect class, idempotency, reversibility, recovery
strategy, and whether they expose an execution receipt. Pawbot derives a stable
operation fingerprint for a call and preserves it through a runtime checkpoint.

Read-only and explicitly idempotent operations may be retried automatically.
Unknown, non-idempotent, or irreversible operations stop and require human
confirmation before the same operation is attempted again. Cancellation does
not claim that an external system rolled back an operation.

## Trace, WebUI, and replay

The execution trace includes task-verification events, failed assertions,
operation fingerprints, recovery decisions, Tool policy metadata, and bounded
receipts. WebUI and raw inspection keep these facts separate:

1. Did the current orchestration reproduce the recorded path?
2. Did the original execution contain a Provider or Tool problem?
3. Did the declared task conditions pass?

Record & Replay stores the declarative contract with a sample and applies it to
the replayed result. Replay remains offline and does not execute real Tools or
request a live Provider.

## Validation

The release is covered locally by Ruff, basedpyright, the Agent Harness,
Record & Replay fixtures, the WebUI test suite, and the complete Python test
suite. Release publication should proceed only after the resulting `main` CI
run is green.
